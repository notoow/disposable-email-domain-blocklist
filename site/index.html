Disposable Email Domain Blocklist

Stop throwaway signups at the boundary that matters. Use evidence-backed domain records, a network-free TypeScript matcher, a CLI, and safe Supabase SQL generation.

Short answer: block only active disposable domains with medium or high confidence, keep an explicit allowlist for reviewed exceptions, and enforce the decision on the server before creating the user.

What developers get

Evidence, not mystery strings

Every active disposable record carries a source URL, evidence note, provider attribution when known, and verification dates.

Server-side by default

Use the same policy in Node, Next.js, or a Supabase Before User Created Hook. Client checks never replace enforcement.

False positives are a policy choice

Alias, role, free-provider, low-confidence, disputed, and unknown records are not blocked by default.

Frequently asked questions

What is a disposable email domain blocklist?

It is a maintained set of domains associated with temporary mailboxes, used to stop disposable email signups before an account is created.

Does this block Gmail or Yahoo?

No. Ordinary free providers, aliases, and unknown domains are allowed by default. Only active disposable records with medium/high confidence are blocked.

Where should blocking happen?

At a server route, auth hook, or database boundary. Browser validation is useful feedback but is not a security boundary.
